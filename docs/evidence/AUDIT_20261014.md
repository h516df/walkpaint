# v0.49 对抗审计及 GitHub 研究

范围：GPS连续记录→过滤/暂存→SQLite→当天/累计显示→系统安装；精简后台UI轮询和诊断。本轮不做地图引擎切换、道路插值、社交或云端轨迹。用户批准方案后唯一主写手连续完成，所有个人路线和原图留在本机。

## 已观察、推断、未知

已观察：原代码同坐标46秒放行，RecordedTrail把它断成孤片段，旧painter会挖孔；修复前回归失败，修复后原生像素通过。截图每个点的来源未逐点从本人SQLite核对，不能把这个已证实代码缺陷说成截图每个点的唯一来源。

已观察：本人0.48报告当前服务62秒、持续回调/有效/保存/过滤均0；历史回调约9小时之前。不能把当前无位置解释为静止过滤。可见52且参与0，只能证明该观测没有卫星参与定位；唯一原因仍未知。退出码10是系统用户请求类，不能推断具体操作或厂商策略。

推断并落地验证：连续原始定位被过度稀疏保存时，保存时间间隔可能被误当GPS断档。短时观察窗口保留实际转折/时间锚，同时对真实回调空窗保持断线。用慢行、转弯、静止、跳变、重启以及隔离SQLite批量回滚验证，未重写历史。

## 实际阅读的上游

- [Colota 原生位置提供者](https://github.com/dietrichmax/colota/blob/c55f402dcf34bd45ca136f7b42e96e63682f1ceb/apps/mobile/android/app/src/foss/java/com/Colota/location/NativeLocationProvider.kt)及合并[PR #947](https://github.com/dietrichmax/colota/pull/947)、[PR #641](https://github.com/dietrichmax/colota/pull/641)：参考限时探测、无定位与静止区分；粗糙探测参考点不能让后续好点长期被拒绝。只参考状态/测试思路，没有复制AGPL实现。
- [Android AOSP LocationRequest](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/location/java/android/location/LocationRequest.java)：旧GPS_PROVIDER请求已映射高精度；不能把别的项目FUSED平衡精度问题套到本项目，不能声称改高精度参数就是已证明根因。
- [Google GPS measurement tools格式](https://github.com/google/gps-measurement-tools/blob/b204a4dd0eee7553e7458e572a83a8b8eb01a9b4/LOGGING_FORMAT.md)及MeasurementProvider/UiLogger：短测采用必要的信号元数据，避免NMEA、原始测量、卫星编号、坐标与持续磁盘日志。
- [BasicAirData GPSLogger](https://github.com/BasicAirData/GPSLogger/blob/6ed0080653e62cf8d775497eec30a1b9b0bf2aef/app/src/main/java/eu/basicairdata/graziano/gpslogger/GPSApplication.java)及服务包装、[mendhak/gpslogger](https://github.com/mendhak/gpslogger)：阅读实际服务/状态、超时及记录入口，参考测试边界，不复制GPL代码。
- OpenTracks、OSMDashboard、MapLibre、Fogwalk等查看元数据及相应README/覆盖层资料。OpenTracks/OSMDashboard归档状态纳入选型，未直接集成或改变引擎。一次全文件批量获取失败已换官方原始文件/定点源码读取；没有把失败的获取当作已阅读。

官方核对：[getCurrentLocation](https://developer.android.com/reference/android/location/LocationManager#getCurrentLocation(java.lang.String,android.os.CancellationSignal,java.util.concurrent.Executor,java.util.function.Consumer))可能返回缓存，回调需检查新鲜度；[GnssStatus.usedInFix](https://developer.android.com/reference/android/location/GnssStatus#usedInFix(int))与看见卫星不同；[ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo)用于解释原因码，并先核对进程。

## 优先级

必须修的静止孤点/连续性、恢复反复重注册与当前历史混淆、诊断精简、后台轮询均纳入本轮。结果及实际环境见 [V049](V049.md)。备份预算#51和增量恢复#52继续高优先级；GPX#53依赖恢复完整性；时间播放#54后续独立实现。无证据的物理GPS原因、本人手机FPS和未接入设备路径不宣称已修好。
