# v0.46 同包高德地图验收（2026-10-13）

Issue #47；正式基线 v0.45 / 05f0f9acc3c541c643f2be640d02d30a31e38363，唯一写手 Codex，任务分支 agent/codex/map-history-performance-v046；整合目标 agent/codex/mobile-ui-redesign-v041。本人反馈：切页返回探索卡顿/闪屏、缩放黑雾有延迟、当天回看应呈现当天地图、后台仍运行但没有新 GPS。保留已有 OpenDesign 视觉和底部探索/足迹/我的。

## 已实现行为

- 底部切页保留同一 SDK 地图与相机，避免重复建立 GL 地图、纹理及标记。
- 当天模式统一选择当天足迹、当天迷雾和最后记录位置；定位当天保留所选日；返回全部恢复实时模式。异步结果用场景代次隔离。
- 高德底图保持原生 SDK；已有 Android 覆盖层整帧绘制未知区域、不可变迷雾、缓存路线与位置，消除 SDK GroundOverlay 纹理与边界分开换帧的白块。手势及相机动画期间按 Android 帧回调读取实时投影，不重算每个足迹点。高德取消完成图像后旧有 600ms 额外提交等待；备用地图保持其既有节流。
- 不变足迹/颜色/帧复用 painter；显示缓冲为不可变副本，避免后台 painter 重用 SDK 正在读取的图像。地图加载后独立解决初始取景，缓存命中不再遗漏冷启动定位；覆盖页面只参与触摸命中，不消费子页面的滚动事件，修复滑动误触设置行。
- 可见卫星但参与定位为零，不再无限延后恢复；搜星等待及重新注册限频 180 秒，常规断档阈值 90 秒，仍由既有服务健康周期检查。GPS 来源/精度过滤与 SQLite schema2 不变。
- 缺少新 GPS 的具体年龄与恢复状态留在我的/诊断。首页仍提示明确的授权、GPS 开关、后台、存储与订阅失败。

## 实际验证

331 JVM / 32 Python 通过。7959 点、140 段、116400.947928 米的匿名公开北京测试夹具仅驻留内存，不写 SQLite；测试退出恢复原缓存。旧 0.45 的四次切页都重建地图，ready 时间 1705/989/885/1002ms；旧当天回看断言失败：包含其他日期迷雾。新包四次真实底栏操作保持同一地图。ready 计时仅证明地图生命周期，不是完整帧率或用户手机延迟。

连续按钮缩放中取 25 张过程截图，每张检查 1044 个可独立证明尚未探索的地理采样位置和固定已探索中心，不以最终截图替代过程；另有实际双指缩小/放大、快速连续/反向/最大缩放、SDK 投影对齐验证。截图采样有额外开销，不能宣称每一帧或所有手势零滞后。

真实 UI 路径：首页 → 放大/缩小 → 拖动 → 足迹/探索保留相机 → 定位 → 日历/统计/日期详情 → 当天地图 → 全部 → 我的/滚动/诊断/检查更新 → 冷启动；同一正式包摘要始终核对。五表原数据逐行摘要一致，原 7 行程 / 4865 点保持。分项结果在 [v046](v046/)。

可复用真实入口命令：先在命名守卫允许的独占 AVD 安装同签名正式 APK 和 androidTest APK，再 `python scripts/map_journey_acceptance.py --apk <正式APK> --out <不存在的证据目录> --probe return|history|scene`。该入口不会安装、清数据、修改隐私同意或接触手机，先验摘要、实际 JNI 与 map-loaded，再验行为。
