# v0.39 验收与交付证据

**产品定位（本轮由用户明确）**：这是**记录"我走过哪些路"**的软件，不是导航软件。探索感与记录感优先，导航便利性不是目标。这条决定本轮取舍：未探索区域可以完全不透明，不必为"看清前面的路"留余地。

工作目录 `D:\Worktrees\WalkPaint\dsh-v039-fog`，分支 `dsh/v039-fog`，标签 `v0.39`，code41。

## 一、本轮改了什么

### A 迷雾
- 雾色 `0xB01B2430`（alpha 176/255）→ **`0xFF000000`**（纯黑完全不透明）。旧注释原文是"别把地图遮死"，也就是说"能透过雾看到线路"是当初有意为之，本轮按用户要求反过来。
- 通道 20 米 → **30 米**；羽化 12 米 → **3 米**。
- **删除帧边界渐隐**：以前帧比屏幕小时靠边缘渐隐掩饰，代价是屏幕边露出没雾的底图。现在帧永远比视野宽（视口 + 35%），边界不可能落在屏幕里。
- 无可用视口时不再退回"已走范围"小帧，而是画 **60° 居中大帧**（`FALLBACK_SPAN_DEG`）；`MAX_SANE_VIEW_DEGREES` 由 5° 放宽到 60°，且**两套引擎统一判断**（以前只有备用地图做，高德路径直接采用引擎上报的全世界视口，这正是"打开没雾、放大才出现"的来源）。
- 三处补"立刻重画"：`onResume`、切到地图页、相机回调早于状态刷新时（`fogPaths` 为空先触发一次状态刷新）。
- **图层顺序**：雾改为 `addLayerBelow(..., "wp-painted-outline")`（官方 API），固定在走过的线与蓝点之下；高德侧路径线 zIndex 1/2 → 10/11（地面覆盖物为 9）。原因是纯黑下"谁在雾下面谁就消失"，而雾层以前是"删掉再添加"，每次重加都被顶到最上层。
- **重走幂等**：`segmentsIn` 增加相同线段去重（端点量化到 0.1 像素、A→B 与 B→A 合并）。窄羽化下每圈 alpha 跨度变大，同一段几何画两次在抗锯齿边缘不是幂等的，实测差 16/255；去重后恢复像素级不变。

### B 走过的线（缩到全城要看得见）
- 默认（累计）视图现在也画轨迹线；`TrailShape.network()` 做三件事：dedupe（跨趟合并重复路段）→ **按当前帧裁剪**（屏幕外的历史不发）→ **按当前视野简化**（容差 = 0.75 帧像素，换算上限 60 米）。
- **只在雾图分辨不出通道时才交给地图画**（`NETWORK_BELOW_PX = 2`）：通道在雾图里够粗时，地面已经被挖开，再送一条线只是每 2 秒让 UI 线程重建一次 GeoJSON。
- 选中某一天时始终画当天路线（不受上面的门限影响）。

### C 诊断：一键「记录现场」
- 新增 `FieldRecorder`（纯内存、最近 30 分钟）：每个定位回调（时间/经纬度/精度/来源/是否入库）、每个被丢弃的点及原因、全部事件时间线。**不落盘、不上传**；常驻诊断仍然只存原因码，不含坐标。
- 新增 `FieldReport` + 反馈页「导出记录现场」按钮：连同机型/系统/权限/后台/引擎、相机与视野、雾帧尺寸与覆盖范围、数据库点数与最后一点，输出成可复制/可分享的文本。
- 钩子：`RecordingDiagnostics.event`（一处镜像全部事件）、记录服务的回调/过滤/入库三处。

### D 「我的」第一屏
- 第一屏只留**自动记录开关**与**涂色颜色**；备份、更新、诊断、关于全部进「更多设置」，并去掉"备份与恢复""检查更新"在两处重复出现的入口。

## 二、验收环境（每次运行前重启 AVD）

`emulator-5556` / `WalkPaint_Google_API36`，Android 36 / x86_64；
引擎读回 = **OpenFreeMap 联网备用地图**；**`amap_supported_on_this_device=false`**；
夹具 4865 点 / 7 趟（含相距 12 公里的远簇）；安装包 `app-debug.apk`，`installed_apk_sha256` 与构建产物一致；五种表行数安装前后一致。

**唯一未达标的是 `update_max`，超出 5.8%，如实记为未通过与归因如下，不写成"环境问题"一笔带过**：

1. 同一份代码在主机更空的一轮里 `update_max = 604.7 ms`（限 1200）**达标**，两轮唯一显著差异是主机可用内存（861 MB vs 423 MB）。
2. 同一轮里**我完全没改过**的 `prep_med`（数据库快照与历史分组）是 349.6 ms，项目自己记录的基线是 154.8 ms——**2.26 倍**；而 `update = prep + veil`，最大值随 `prep` 同步变化（232 → 605；350 → 1269）。
3. 项目在 V037 已记录过同一现象："主机可用内存只剩 477–734 MB，所有计时项整体约 2 倍恶化（连未改动的 `prep_med` 也从 259 ms 涨到 503 ms）"。
4. 本轮已经**主动去掉了新功能带来的 UI 成本**：把"走过的线"改成只在雾图分辨不出通道时才交给地图，`ui_med` 由 24.4 ms 降到 15.0 ms（限 20）。

也就是说：新功能在 UI 线程上的开销已消除；剩下的最大值尖峰落在未改动的旧路径上，且与主机负载同步。**但这不等于真机没问题**——真机上的观感与帧率必须由你在手机上确认。
