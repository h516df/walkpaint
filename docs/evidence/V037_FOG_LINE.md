### 复核复检：上一轮是假通过，已修

复核指出 `fixed/map-far-cluster.png` 其实是近处（Centre Georges Pompidou / Rue du Renard），与 near 图同地。原因查清：

- 脚本先点两天前那天（相机对焦远簇），随后点了"返回全部探索"；该按钮走 `clearDaySelection()` → `follow.locate()`，**把相机拉回人的位置**，于是截到的还是近处 ✗。
- 断言只看颜色比例，没有校验相机真的在 `2.5163` 附近，所以近处画面也能"通过" ✗。

修法：

1. **每张截图绑定实际场景**。App 在相机空闲时写一行 `WalkPaintCam`：相机中心/缩放、当前是累计视图还是某一天、人的实际位置、可见 bounds。脚本在每次截图后读这一行并断言：
   - `map-far-cluster`：相机中心在远簇 ±0.003° 内、`day=cumulative`；
   - `map-between-clusters`：相机经度落在两簇之间（2.39–2.48）、`day=cumulative`；
   - `map-near-cluster`：相机回到近簇 ±0.004°、`day=cumulative`；
   - 三张图都断言**人的位置仍在近簇**（`fixLon` 未变），证明移动的是地图而不是人。
2. **用真实手势走过去**。不再靠"点某天 + 返回"跳转：脚本在累计视图里用 `input swipe` 连续拖动（`pan_camera`），每拖几次读一次相机记录，直到真的到达目标；中途经过两簇之间时截 `map-between-clusters`。
3. **证据**：`fixed/acceptance.json` 里 `scene_far_cluster` / `scene_between_clusters` / `scene_near_cluster` 记录了三张图对应的实际相机状态；`fixed/map-far-cluster.png` 现在显示的是远簇街区（Stade Municipal / Rue Raimond Louviot），`between` 图是两簇之间的未走过地面。

### 指标改名（复核第 3 条）

- `activity_launch_ms` = `am start -W` 的 TotalTime，**只说明 Activity 窗口起来了**；MainActivity 的地图状态是异步刷新的，所以它不是"地图可用"。
- `map_presented_ms` = 从启动到**截图里真的能看到雾**的时间（截图像素判据，见第 5 节）。轮询一次截图约 2–3 秒，所以它的分辨率就是这个量级，报告里如实标注。

## 4. 卡顿的归因（回答"是否阻塞 UI"）

`PerfTrace`（仅 debug 调用点）把成本拆开，同一次运行内测得：

| 指标 | 数值 | 说明 |
|---|---|---|
| 迷雾增量重绘（每个新定位点） | 中位 12.6 ms / 最大 17.4 ms | 后台线程 |
| 迷雾全量重建（换视野/换色） | 最大 100.7 ms | 后台线程 |
| 平移/缩放触发的重画 | 见 `pan_n / pan_med_ms / pan_max_ms` | 后台线程，节流 500 ms，落在节流窗口里的请求会合并成一次而不是丢弃 |
| 把雾图交给地图 | 平均 6.0 ms / 最大 13.9 ms | 唯一在 UI 线程上的部分 |
| **UI 线程每次更新** | 中位 **5.2 ms** / 最大 **16.6 ms** | 约一帧；这是会掉帧的那部分 |
| 整次更新（稳态） | 中位 164.6 ms / 最大 195.5 ms | 其中 **154.8 ms 是既有**的数据库快照与历史分组 |
| 启动后第一次更新 | 3078.5 ms | 冷启动成本，单独记录，已从稳态统计里剔除 |

- 既有那 154.8 ms 跑在后台线程，UI 线程每次只花约一帧（最大 16.6 ms）；**它不阻塞 UI**。这部分本轮没有改动，也不归功于本轮修复。
- 拖动时不再要求"零 UI 工作"：雾要跟着视口走，本来就要交接一次图。现在断言的是"拖动期间没有状态更新 + 单次重画不超过 800 ms"（见 `gesture_counter_delta` 与 `pan_max_ms`）。

## 5. 迷雾的像素自证（复核第 2 条）

`app/src/androidTest/java/cn/walkpaint/FogPixelProbe.kt` 通过现有验收入口（`am instrument -e fogPixelProbe true`）读**渲染出来的位图**，而不是只判断常量。它检查：

1. 走过的走廊只带自己的染色（alpha ≤ 110 且偏绿），没走过的地方仍在雾后（alpha > 0x60）；
2. 走廊外雾是**渐变回升**：至少 4 个不同取值、没有一步跳超过 64/255、并且在涂层之外单调回升到满强度；
3. 帧边界**在真实距离上渐隐**（取样横跨整个渐隐带，首点 ≤ 8、末端 ≥ 0xA0、至少 4 个取值、单调）；
4. **重复经过同一条街，像素完全不变**（第二次经过与第一次逐像素比对，容差 8/255）；
5. **追加轨迹不得把已探索地面重新盖雾**：先只画一条街，记下整行像素；再追加"平行偏移 8 米的一趟 + 一条交叉街 + 一段新尾巴"，逐像素比较——原先已清空的位置不允许出现"重新变回雾色且更不透明"的像素（涂上颜色不算，按颜色区分雾/颜料）；
6. 以 12 公里外地面为中心的视口帧**包含那块地面**；
7. **比旧上限更宽的视野也要被完整覆盖**：30 公里跨度的视口，帧必须包含它的四角（否则四角无雾＝看起来像已探索）。

**这套断言当场抓到了三个真问题**（常量测试全都漏过）：

| 抓到的问题 | 根因 | 修复 |
|---|---|---|
| 走廊边缘是硬边，外面还有一圈只剩染色的"亮环" | `PorterDuff.CLEAR` 不是按 alpha 缩放，而是"覆盖到就清零" | 改用按 alpha 缩放的擦除 |
| 帧边界只在 1 像素宽处渐隐 | `fadeEdges` 复用了 **STROKE** 画笔，`drawRect` 只画了矩形轮廓 | 单独用 FILL 擦除画笔 |
| 反复经过同一条街，雾越擦越薄 / 染色越叠越深 | `DST_OUT` 与叠加式染色都会累积 | 走廊改为**逐层 SRC 替换**（由外向内一层层换成更淡的雾，再换成自己的颜色），重复经过落在同一组值上 |
| **追加新线段时，它的外环把先前已探索的地面重新盖雾**（复核在截图上看到的深色圆环/圆头印记） | 逐"线段"绘制时，后一段最外层的高 alpha 雾会覆盖前一段已清空的地面；只测"完全相同的路径重画"发现不了 | 改为**逐"环"绘制**：先把所有线段的最外圈铺完，再铺下一圈……最后统一上色；并且每次更新都从几何整体重画，使结果只取决于几何 |
| 同一张缓冲区复用后雾越来越深（实测 alpha 215 > 雾本身的 176） | 复用位图时用 `SRC_OVER` 铺雾会与旧内容叠加 | 铺雾改为 `SRC` 整体替换，并改成双缓冲（地图读一张、画笔写另一张） |

后两条都是**这一轮新加的像素断言当场抓出来的**：前者对应复核在截图里看到的圆环，后者是我自己在改双缓冲时引入的回归。

修复后：`FOG_PIXEL_PROBE_PASS`。

| 阶段 | 判据 | 说明 |

| 现在（恢复原判据） | `ui_med ≤ 20`、`ui_max ≤ 120`、`upload_med ≤ 20`、`veil_inc_med ≤ 30`、`veil_inc_max ≤ 250`、`update_med ≤ 400`、`update_max ≤ 1200`、`pan_max ≤ 800`、`first_update ≤ 6000` | 见下 |

**这些确实是改过的判据，不是"旧判据已经通过"。** 早期三次失败都是真实失败，报告与截图保留在 `verification/fog-line/after/history/`。

改判据的理由逐条如下：

1. **启动后第一次更新单独剔除**（`first_update_ms` 单独记录）：它包含打开数据库、读全部点与 JIT 预热，是冷启动成本，由启动指标覆盖。
2. **迷雾重绘阈值按产品要求定**：迷雾重绘在后台线程，不可能掉帧；30 ms / 2 秒约等于单核 1% 的占用，250 ms 只是病态上限。
3. **UI 判据曾放宽，现已恢复原值并真的达标**：先按"谁负责"拆出 `upload_med`（交接自身），再用实测把整体 UI 成本压下来——分解计时显示 UI 块里赋值只占 4.6 ms、**交接占 55.7 ms**，而交接的成本就是那张位图的上传。把掩膜上限 768 → 512、并跳过未变化的 GeoJSON 提交后，同一台机器（且主机很忙、`prep_med` 高达 1610 ms）实测 `ui_med 18.3 ms`、`upload_med 6.9 ms`，因此**恢复原判据 `ui_med ≤ 20 / ui_max ≤ 120`**，没有靠调阈值通过。
4. **拖动判据改成"真实并发"**：不再断言"拖动期间零更新"（那是把压力抽掉），改为**边持续注入定位边拖动**，并断言拖动期间确实发生过状态更新（`update_n` 增量 > 0）；没有重叠就报未测。
5. 采样条件同时修正：注入间隔 2 秒 → 3 秒、每次运行前重启 AVD、跑完前不与其他构建共用同一台被压过的模拟器；并记录主机可用内存。

## 6b. 环境层：把"看起来像产品回归"的三类症状分开（有复用价值）

反复出现的三类症状——**安装后 `dumpsys package` 成功却读不到版本**、**截图里雾"消失"（`veil_ratio` 0.01）**、**数值忽好忽坏**——经最小定位分成两层，不能混为一谈：

| 层 | 观察 | 处理 |
|---|---|---|
| harness 查询 | `run()` 在非零退出/超时时抛异常；实际遇到的是"命令成功、输出为空"（安装刚结束时 PackageManager 未就绪） | 改为轮询并记录 `version_query_raw` / `version_query_attempts`，可区分空输出 / 错误串 / 解析失败 |
| 模拟器窗口 | 截图上是 **"System UI isn't responding"** 弹窗；`mFocusedApp=cn.walkpaint/.MainActivity` 但 **`mCurrentFocus=null`**，而设备 Awake、屏幕 ON | 只读工具 `inspect_emulator.py` 判定 `blocked / foreground_unobserved / stage=foreground_1`；执行一次 `am force-stop com.android.systemui`（不重启 AVD、不动数据）后复测 `observed_ready / two_matching_observations`，`mCurrentFocus` 恢复为 App 窗口 |

观测文件：`verification/ready-r-round2.json`、`ready-r-round2-app-foreground.json`、`ready-r-round3-after-systemui-restart.json`、`ready-r-round4.json`。

边界（工具自己声明）：`observed_ready` 只说明这两个瞬间版本/前台可观测，**不证明渲染正常、没有遮挡、性能合格，也不证明 APK 哈希相同**；因此安装指纹（`installed_apk_sha256` 与候选哈希比对）与产品场景断言一律保留，`blocked` 时不得把颜色或空样本判为产品回归。

## 7. 未验收 / 已知限制

1. **高德 ARM 真机路径未验收**：`AmapPlatform.supported` 只接受 `arm64-v8a` / `armeabi-v7a` 进程，本机 AVD 是 `x86_64`，只能跑备用地图引擎。手机上的迷雾观感、拖动帧率、涂色深浅必须由用户真机确认。**备用地图通过不等于高德通过。**
2. **视野上限已修（复核第 4 条）**：以前帧在跟随视口时仍被 20 公里上限裁剪，视野更宽时四角没有雾，看起来像"已探索"。现在**跟随视口的帧不再设上限**，宽视野只是把同一张图摊得更粗（细节变粗，但未知区域仍然被遮住）；边界渐隐仍是"帧尺寸 14% 与 900 米取小"，所以宽视野下渐隐带不会吃掉整张图。像素探针第 7 条断言 30 公里跨度的视口四角都被帧包含。**仍未在真机上看过极宽缩放的观感。**
3. **`map_tab_ready_ms` 不可比**：它靠轮询 `uiautomator dump` 判断页面就绪，每次 dump 要 1.5–3 秒，两个版本的差值被测量工具吃掉，只用于确认"页面确实起来了"。
4. **早先一处措辞是错的**：先前报告说 `map-tab-return` 截图"雾仍在"，用海军蓝面罩判据复测那张图只有 0.001（即**没有雾**），当时把地图要素看成了雾。
5. **本机这版 MapLibre（13.5.2）上 `ImageSource.setImage/setCoordinates` 不刷新画面**：这是**实测**结论，不是从注释推断的——把交接改回"原地 setImage"后，用同一条探针第三次受控移动移到 12 公里外的远簇，截图统计为 `veil_ratio=0.000 / tint_ratio=0.000`（对比重建 source 时的 0.863 / 0.022），即地图上什么都没有。因此每次改动都重建 source+layer；为控制 UI 线程成本，交接做了合并（`VEIL_HANDOVER_MS=600`，走路时雾最多滞后约 1 米）。这是本机行为，未逐版核对上游。
6. **户外长时间后台记录**仍待真机。
7. 备用地图需要联网取瓦片；高德路径未测。
